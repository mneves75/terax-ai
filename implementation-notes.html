Final Decisions And Tradeoffs

  • Kept the Codex provider keyless because host Codex owns authentication and model configuration. Terax now verifies CLI availability/version before presenting it as connected.
  • Scoped Codex sessions by workspace root, cwd, workspace environment, and CLI path so a persisted Codex thread is not reused after the workspace/CLI changes.
  • Kept backend file and shell authorization in Rust, not only in the renderer. Renderer approval remains UX state; backend workspace checks are the enforcement boundary.
  • Allowed multi-line shell snippets while blocking recursive root/home deletes, disk-formatting patterns, Unicode bidi overrides, and pipe-to-shell install patterns.
  • Rejected renderer-controlled access to arbitrary private network addresses in ai_http_stream. Local model loopback endpoints remain allowed with opt-in.
  • Ignored local runtime artifacts .omc/ and .playwright-mcp/ through .gitignore; they are not part of the product diff.

2026-05-31 Verification And Finalization Pass

Critical finding: the in-flight read-authorization refactor left the Rust test suite uncompilable.

  • The prior pass moved the fs read commands (fs_read_dir, list_subdirs, fs_search, fs_list_files, fs_grep, fs_glob) onto authorize_read_path(registry, ...) and added *_inner variants taking &WorkspaceRegistry. The integration test src-tauri/tests/fs_search.rs was renamed to call the *_inner functions but the new ®istry argument was never passed, so cargo test --locked and cargo clippy --all-targets both failed to compile the fs_search test (27 errors, E0061).
  • This was masked earlier because the verification command piped cargo test through tail, so the recorded exit code came from tail (0), not from cargo. The build was actually red.
  • Fix: passed &fx.registry to every *_inner call; used &WorkspaceRegistry::default() for the two non-fixture error-path tests (which fail at canonicalize on a nonexistent path regardless of registry, keeping the import used).
  • Added two regression tests that lock the new invariant directly: grep_unauthorized_root_errors and read_dir_unauthorized_root_errors assert a real, readable directory that was never authorized is refused.

Manual review of the in-flight security + accessibility changes (no critical/high issues found).

  • Read-path authorization cannot break the explorer: bootstrap_registry authorizes the resolved launch dir and home; lib.rs additionally authorizes the CLI launch dir; terminal cwds are authorized as they arrive via workspace_authorize. is_authorized uses target.starts_with(root), so descendants of any authorized root pass. Confirmed by existing fixture tests (subdir accepted, symlink escape rejected) plus the two new tests.
  • inert replacing aria-hidden on hidden tab panels and the collapsed composer is correct for React 19 (typechecks); it only blocks focus/interaction/AT and does not stop background PTY/dev-server streaming. When a tab activates the attribute is removed before focus, so terminal focus still works.
  • iframe sandbox split is a strict tightening: external URLs lose allow-same-origin, allow-downloads, and clipboard; loopback keeps them; allow-top-navigation* is never granted. Covered by PreviewPane.test.ts.
  • Stricter check_shell_command (rejects all control chars incl. newline) is an intentional security tradeoff: it prevents smuggling a second command past the single-line approval card the user sees. Multi-line AI commands must be split. Documented as a deviation from the earlier "allow multi-line shell snippets" decision.
